# 多书主题合成流程

## 启动条件与工作目录

只有用户明确指定本次书籍目录时启动。目录中有哪些书，就处理这些书；不自行选用仓库里的示例语料。把提取缓存、阅读审计和生成 Skills 放在元 Skill 目录与书籍目录之外的运行目录。用户指定输出目录时采用该目录；未指定时选择可写的同级目录并告知路径。

## 1. 初读与分类

先检查提取质量。逐书读取目录、导言、全书结构和代表性正文，写明作者要解决的核心问题、方法骨架、适用范围和关键任务。根据**书实际讨论的问题**建立主题；不要从目标下游产品预先倒推主题。每本书一个主要主题，跨主题使用单独注明。

初始分类是可修订假设。某主题若包含两个完全不同的用户任务、输入和输出合同，就拆分；两个主题若常被同一请求同时触发且本质是同一任务，就合并。每次变动在 `theme-map.md` 记录原方案、证据与新归属。**分类完成后，每个主题必须生成一个独立 Skill。**

## 2. 逐书精读与覆盖审计

每本书建立两份文档：

- `overview`：核心问题、全书结构、关键论证、术语、作者案例及局限。
- `coverage`：关键任务或方法、原书定位、候选去向（纳入主题方法卡／参考／待核查／排除）与理由。

大书可分块读，但要覆盖整书各主要部分，不可只搜索预设关键词或只读被索引摘要命中的位置。目录、版权页等噪声不算阅读覆盖。分片 ID 是检索定位，不一定是原书真实章节号。对 OCR、EPUB 切分异常保留警告。

## 3. 主题内提取与跨书仲裁

从用户任务倒推需要的方法。对每个任务列出所有候选来源，再做三关：原文足以支持吗；新输入能执行吗；能提升任务结果吗。之后比较方法之间是互补、层级不同、互斥还是同义。为每条最终执行规则记录选择条件、舍弃项和来源定位。

**融合不是平均或并列书摘。**可用作者 A 的诊断框架、作者 B 的操作步骤和作者 C 的反例构成流程；也可只采用一位作者的完整方法，其他书在边界或替代方案中体现。不能因为一本书出现在来源列表，就宣称它支持卡片所有内容。

对争议、原文缺口及底模效果不确定的内容，标为待核查；不要转写成绝对命令。具体数值要标清是物理公式、书中经验、项目约定还是需要实测的模型提示建议。

### 生成前的用户告知

**全部指定书籍完成阅读覆盖审计、最终主题边界修订后，先向用户报告最终有 K 个主题、每个主题的书籍归属及分组理由。**这发生在写第一个主题 Skill 之前。若有提取失败或未读完的书，说明现状，不能把候选分类说成最终分类。用户没有提出调整时，继续生成 K 个独立 Skills；不额外等待批准。

## 4. 封装独立 Skill

一个主题一个目录，先定该主题特有的任务和相邻边界，再写 `SKILL.md`。入口保留最关键决策与执行路径；较长方法、案例和证据放 `references/`。每个 Skill 要在不安装其他生成 Skill 时，仍可完成自己的核心任务。方法卡可多张，但不能代替入口。最终 **K 个主题对应 K 个新 Skills**，不是 K 张 MD 卡，也不是一个总 Skill。

主题 Skill 不默认接入任何现有消费端产品。对接 `hs-dramaskill` 是独立的后续适配工作，不改变本次产物形式。

## 5. 测试与发布

为每个 Skill 写正例、负例、相邻 Skill 竞争例及实际输出例。执行者面对真实请求运行 Skill，保存实际输出与判断；不要把期望答案塞给执行者。测试失败时追溯是分类、阅读、仲裁、触发还是执行合同的问题，修对应层后重测。

最终对照 `books.json` 检查：成功来源数、审计完成书数、最终主题数、独立 Skill 数、测试通过数。仅当完整覆盖且每个主题的独立执行得到验证时，才报告项目完成。
